## What you get

<CardGrid>
	<Card title="Rooms" icon="laptop">
		Join a room by name. Every other peer in it becomes a participant with its own `RTCPeerConnection`, and
		leaving closes them all.
	</Card>
	<Card title="Data channels" icon="comment">
		Send text or binary data to one participant or the whole room. What you send before the channel opens
		waits, and goes out in order.
	</Card>
	<Card title="Media at any time" icon="star">
		Share a stream when you join or later. Connections renegotiate by themselves, and offers that cross are
		resolved with perfect negotiation.
	</Card>
	<Card title="Your signaling" icon="random">
		socket.io with the client that matches your server, `BroadcastChannel` between tabs with no server, or
		your own in two methods.
	</Card>
	<Card title="Typed" icon="approve-check">
		Written in strict TypeScript: event names and what they carry are typed, and so is every signaling
		message.
	</Card>
	<Card title="Nothing else to install" icon="rocket">
		An ES module with no dependencies. Its tests run real connections in Chromium, Firefox and WebKit.
	</Card>
</CardGrid>

## Coming from v3

<div class="landing-lead">
	Rooms, participants and their events are the same. The `EventDispatcher` is gone: PeerData takes the
	signaling, SocketChannel takes a socket you create, and connections negotiate by themselves.
</div>

<div class="compare">

```ts title="v3"
const dispatcher = new EventDispatcher();
const peerData = new PeerData(dispatcher, servers);
new SocketChannel(dispatcher, 'http://localhost:8080');

const room = peerData.connect('room');
room.on('participant', (participant) => {
  participant.addStream(stream);
  participant.renegotiate();
});
```

```ts title="v4"
const peerData = new PeerData(
  new SocketChannel(io('http://localhost:8080')),
  { configuration: servers },
);

const room = peerData.connect('room');
room.on('participant', (participant) => {
  participant.addStream(stream);
});
```
